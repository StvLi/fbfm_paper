# Related Works 写作反馈与改进建议

本文档基于 FBFM 的 Related Works 初稿整理。初稿已经具备很好的研究敏感度：它没有停留在罗列模型名称，而是主动尝试建立 WAM 架构、执行反馈和受约束生成之间的关系。尤其是对 Fast-WAM、RTC 和 Feedback World Model 的选择，说明作者已经找到了与 FBFM 真正相邻的问题。后续修改的重点，是把这些有价值的判断放进更完整的历史脉络，并进一步提高事实边界、评价语气和引用组织的严谨性。当前候选文献与检索方向整理在 [Related_Works_Literature_Map.md](Related_Works_Literature_Map.md)。

## 1. 初稿中值得肯定和保留的部分

### 1.1 已经形成了清晰的架构意识

初稿能够区分先生成未来状态、再生成动作的 WAM，与在同一生成过程中联合建模状态和动作的 WAM。这一分类对于解释 FBFM 为什么需要同时覆盖两种生成接口非常重要。正式稿只需将名称统一为全文采用的 `stage-wise generation` 和 `joint generation`，并避免把 iterative joint generation 写成一次 forward pass。

### 1.2 Fast-WAM 的对比角度很好

“Fast-WAM 保留训练期的视频协同建模，但在测试时取消显式未来想象；FBFM 则研究保留测试时未来状态生成时，如何用真实观测校正它”是初稿中很成熟的一处定位。它没有简单判断哪一种路线更好，而是指出两项工作回答的是互补问题。这种写法值得保留，也是 Related Works 中较理想的客观比较方式。

### 1.3 抓住了 FBFM 的技术来源链

初稿把图像逆问题中的 constrained sampling、RTC 的 action inpainting 和 FBFM 的 state--action feedback 联系起来，这条线索准确触及了 FBFM 的方法来源。相比按年份罗列文献，这种“技术概念如何迁移到新问题”的组织方式更能帮助读者理解贡献。

### 1.4 能主动寻找最接近的同期工作

初稿没有回避 RTC、RA-DP 和 Feedback World Model 等强相关工作，而是尝试说明彼此的研究对象和反馈机制。这是很好的科研写作习惯。面对相近工作，主动、准确地说明联系和差异，比弱化或回避它们更能建立可信度。

## 2. 当前版本可以进一步改进的地方

### 2.1 文献脉络还不完整

初稿直接从 VLA/WAM 开始，随后进入执行反馈和受约束采样，因此缺少两个必要过渡：一是 diffusion、Flow Matching 和 inverse problems 如何从视觉生成发展而来；二是生成模型如何从轨迹规划和 Diffusion Policy 进入机器人动作生成。没有这些过渡时，读者容易把 ΠGDM、RTC、WAM 和 FBFM 看成突然拼接的概念。

改进方法：不要平均扩写所有背景，而应建立三条逐步收窄的文献链：

1. 生成模型、inverse problems 与 world models；
2. diffusion/Flow-Matching robot policies；
3. inference-time guidance、异步执行与在线反馈。

每条线都从广义背景开始，但最终必须落回 FBFM 所解决的问题。

### 2.2 架构描述中混入了事实性过度简化

`joint-prediction WAMs ... in a single forward pass` 容易使读者误以为 joint generation 不需要迭代求解。更准确的说法是：状态和动作共享一个迭代式 diffusion/flow process，并在联合变量或共享网络中共同生成。类似地，“两类 WAM 都使用 KV-cache refresh”也不宜作为类别级结论，因为 observation history、latent buffer 和 KV cache 的更新方式取决于具体模型。

改进方法：区分“本文为了分析而采用的抽象接口”和“某篇论文的具体实现”。类别级描述只保留共同性质；cache、buffer、VAE stream 等内容必须绑定具体引用，并优先放在 Experiments 而不是 Related Works。

### 2.3 对相邻工作的概括需要保留完整机制

RTC 不是只冻结一个 prefix。它同时涉及确定执行的 frozen prefix、用于平滑衔接的 soft overlap 和自由生成的 suffix。把 RTC 简化为 fixed prefix constraint，会低估其对跨 chunk 连续性的完整处理，也会使 FBFM 的真实增量难以准确呈现。

Feedback World Model 的收敛性分析针对 latent observer，而不是 pseudoinverse guidance。RA-DP 的 sampling-time guidance 可以不重新训练，但其 heterogeneous-noise action queue 依赖专门训练方式。因此，不能只根据论文名称或 abstract 中的 `training-free` 判断整个模型是否是对现有 policy 的即插即用修改。

改进方法：对最接近的工作至少核对 abstract、method overview、关键公式和 limitations。每篇文献用两行笔记分别记录“论文明确声称了什么”和“我们据此作出的比较”，不要把后者写成前者的原始结论。

### 2.4 FBFM 的表述有时过强

`hard measurement constraints`、`at every flow step` 和 `full future visual trajectory` 都可能超出方法或模型的普遍适用范围。FBFM 支持 binary mask，也允许 confidence weighting；guidance 提供条件速度修正，但不应在没有证明和实验时声称所有约束都被精确满足。反馈也只能在到达并被 solver 读取后影响后续 evaluation。

改进方法：把绝对表达改成带有对象、条件和范围的准确表达，例如：

- `masked, possibly confidence-weighted constraints`；
- `at each solver evaluation using the feedback currently available`；
- `time-aligned latent-state slots generated by the WAM`。

这类限定不会削弱贡献，反而会使技术主张更可信。

### 2.5 比较维度需要统一

当前稿件有时比较架构，有时比较训练方式，有时比较反馈变量，导致 RTC、RA-DP、FWM 和 FBFM 看起来处在同一条单轴排名上。事实上它们分别改变了不同层次的问题。

改进方法：对近邻工作统一使用以下四个维度：

- **反馈对象**：动作、单步状态，还是多步 latent future；
- **反馈位置**：外层 context update、独立 policy guidance，还是 active generative flow；
- **时间粒度**：chunk boundary、denoising step，还是与 chunk slot 对齐的动态反馈；
- **训练要求**：需要专门训练、需要额外模型，还是直接作用于冻结模型。

这样既能准确赞赏已有贡献，也能自然说明 FBFM 的增量。

## 3. 如何进行客观、温和而有辨识度的评价

Related Works 的目标不是证明前人工作“不好”，而是说明每项工作解决了什么、它的设计边界是什么，以及本文研究的问题为什么仍然存在。推荐采用“贡献在前，边界在后”的句式。

### 3.1 推荐句式

> RTC enables asynchronous execution of pretrained flow policies by treating committed actions as inpainting constraints. Its formulation focuses on cross-chunk action continuity, whereas FBFM additionally uses newly observed latent states to re-ground the future-state stream of a WAM.

第一句先准确说明 RTC 的贡献，第二句再限定问题范围并引出 FBFM，不需要使用 `fails to` 或 `cannot`。

> Feedback World Model independently demonstrates the value of closing the prediction--observation loop at inference time through an observer-style latent correction. FBFM studies a complementary sampling-time formulation in which time-aligned state and action measurements directly modify an active WAM flow.

这种写法承认同期工作的价值，同时通过 `complementary` 和明确机制区分避免优劣化判断。

> Fast-WAM shows that video co-training can remain beneficial even without explicit future imagination at inference time. FBFM instead addresses WAMs that retain such future generation and asks how it can be re-grounded during execution.

这里不把两项工作写成互相否定，而是说明各自的研究条件。

### 3.2 应谨慎使用的词

除非有系统综述或论文原文支持，应谨慎使用 `first`、`only`、`all`、`dominant`、`exclusive`、`guarantees`、`fails` 和 `fundamentally incapable`。可以优先使用：

- `primarily focuses on`；
- `is designed for`；
- `does not explicitly model`；
- `has not been established for`；
- `under the setting considered in this work`；
- `to our knowledge`，并在使用前进行充分检索。

## 4. 推荐的 Related Works 组织方式

正式排版可以不设置三个可见小标题，但段落应遵循以下内部结构。

### 4.1 Generative Modeling and World Models

用少量经典工作说明 diffusion 与 Flow Matching 最初作为连续生成模型出现；随后通过 RePaint、ΠGDM 和 flow-based inverse methods 引入已知观测、mask 和 inverse measurement constraints。再从 latent world models 过渡到 action-conditioned video simulators 和 WAM，最后用 LingBot-VA、DreamZero 与 Fast-WAM 说明本文面对的测试时未来生成场景。

本部分的落点不是介绍所有生成模型，而是建立两个前提：生成轨迹可以看作连续流；已知测量可以在不重新训练生成器的情况下约束采样。

### 4.2 Diffusion and Flow-Matching Policies for Robot Control

从 Diffuser 将 diffusion sampling 用于轨迹规划开始，过渡到 Diffusion Policy 将 action chunk 直接作为条件生成对象，再介绍 RDT 等工作体现的规模扩展。随后明确 diffusion 和 Flow Matching 是相关但不同的连续生成参数化，引用早于 \(\pi_0\) 的 Flow-Matching robot policy，最后说明 \(\pi_0\) 如何把 Flow-Matching action expert 扩展到大规模通用 VLA 并带来高频、灵巧控制性能。

本部分应避免声称 \(\pi_0\) 是第一个机器人 Flow-Matching policy。更准确的贡献是：它是早期将 Flow Matching、action expert 和大规模通用 VLA 结合并展示显著性能跃迁的代表性工作。

### 4.3 Inference-Time Guidance, Asynchronous Execution, and Feedback

先说明 action chunking 带来的 inference latency 与跨 chunk 连续性问题，再讨论 BID、RTC、RA-DP 等异步或高频执行方法。随后引入 Feedback World Model 和近期 training-free WAM steering 工作，说明真实执行反馈正在成为独立研究方向。最后仅用一到两句定位 FBFM：它把 RTC 风格的受约束采样扩展到 WAM 的 state--action generation，并允许新到达的 latent-state measurements 进入 active flow。

这一部分可以出现 FBFM，但不展开公式、掩码构造或 stage-wise/joint 的实现细节；这些内容属于 Method。

## 5. 初稿片段的建议去向

| 初稿内容 | 建议处理 |
|---|---|
| WAM 的两种生成架构 | 保留思想，统一为 `stage-wise generation` 和 `joint generation`，移到第一主题后半段 |
| Fast-WAM 的互补场景 | 基本保留，作为第一主题的收束 |
| RT-1、RT-2、OpenVLA、\(\pi_0\) | 移入第二主题；区分 autoregressive VLA 与 generative action expert |
| RTC、RA-DP 与 cache refresh | 重写后放入第三主题；不要把模型专用 cache 机制推广为类别结论 |
| Feedback World Model | 保留其 observer-style feedback 定位，修正收敛性证明对象 |
| ΠGDM 到 RTC 再到 FBFM | 拆分使用：inverse-problem 背景放第一主题，机器人执行迁移与增量放第三主题 |
| FBFM 的 Jacobian/VJP 细节 | 从 Related Works 移到 Method，只在此处保留 sampling-time constrained guidance 的概括 |

## 6. 推荐的后续写作流程

1. 每个主题先建立约 20 篇候选文献，而不是直接写英文段落。
2. 为每篇文献记录它支持的具体句子、与 FBFM 的关系和是否必须引用。
3. 优先精读直接前驱与近邻工作；历史背景文献只核对与本文有关的核心主张。
4. 每个主题先写一条论证链，再选择能够支持链条的文献，避免按论文逐篇摘要。
5. 写完后检查每项评价是否同时包含已有贡献和适用边界。
6. 将无法从原文定位的强判断删除、弱化或标为待核验。
7. 最后统一术语，并检查 Related Works 没有提前泄露 Method 和 Experiments 的具体实现。
